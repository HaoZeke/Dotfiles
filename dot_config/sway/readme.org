* Sway Session Modes And Workspace Controls

This machine now has three separate session concepts, and they are meant
to be read literally. In the top bar they are now summarized into one
compact mode block so they do not eat the whole status line.

| Bar label | Meaning | Locking | Idle sleep | Performance backend |
|-----------+---------+---------+------------+---------------------|
| = AUTO= | default behavior | yes | normal | unchanged |
| = AWAKE= | block idle-triggered sleep only | yes | blocked | unchanged |
| =BOOST ON= | request the performance profile only | unchanged | unchanged | on |
| =FOCUS ON= | =AWAKE + BOOST= together | yes | blocked | on |
| =MIXED= | unusual combination, usually legacy/manual state | varies | varies | varies |

So the intended reading is:

- =AWAKE=: keep the machine awake, but still let the normal dim / lock /
  DPMS path happen.
- =BOOST=: ask the power backend for the faster profile without changing
  lock or idle policy.
- =FOCUS=: turn on both =AWAKE= and =BOOST= at once.

The old "presentation" idea still exists in =rg-caffeine= as a CLI mode,
but it is not the main keyboard path anymore. The keyboard path is the
clearer =focus = awake + boost= behavior.

* Top bar block

The upper bar now uses one compact mode block instead of separate coffee /
boost / focus segments.

| Bar text | Meaning |
|----------+---------|
| = Auto= | default behavior |
| = Awake= | idle sleep blocked |
| = Boost= | performance profile only |
| = Focus= | awake + boost |
| = Mixed= | non-default combination |

Color intent:

- =Auto=: neutral / idle
- =Awake=: informational, should read as "special but not aggressive"
- =Boost=: warning-like, because it is the more battery-expensive mode by itself
- =Focus=: positive / active, because it is the deliberate combined mode
- =Mixed=: warning-like because it usually means an unusual partial/manual state

Mouse actions on that block:

- left click: toggle =AWAKE=
- middle click: toggle =BOOST=
- right click: toggle =FOCUS=
- wheel up: timed =AWAKE= for 2 hours
- wheel down: restore default idle policy

* Workspaces

Workspaces now have semantic names such as =7: read=, but the keyboard
path should still be the number row.

- =$mod+1 .. 0=: switch by workspace number slot
- =$mod+Shift+1 .. 0=: move the focused window by workspace number slot
- =$mod+,= / =$mod+.=: previous / next workspace on the current output
- =$mod+Tab=: back-and-forth between the last two workspaces
- =$mod+g=: temporary =goto= mode for semantic workspace jumps
- =$mod+/=: open a rofi workspace chooser

The workspace chooser now:

- pins the current workspace first
- shows the output name
- shows a simple occupied / empty marker

The number-row bindings use sway's =workspace number ...= form, so the
keyboard targets the numbered slot rather than requiring the full label.
That is meant to avoid the "is it =7= or =7:read=?" confusion.

On reload/startup, =~/.local/bin/rg-workspace-sync= renames plain numeric
workspaces like =7= into their semantic labels like =7: read=. That keeps
the keyboard model numeric while making the strip readable again.

The =goto= mode is a short mnemonic leader rather than another full-time
modifier chord set:

- =r= -> =7: read=
- =n= -> =4: note=
- =f= -> =6: file=
- =w= -> =2: web=
- =c= -> =3: code=
- =m= -> =8: media=
- =s= -> =10: sys=

The mode exits immediately after a jump, or with =Escape= / =Return=.

* Desktop palette

=~/.local/bin/rg-desktop-help= provides a compact keyboard-first control
palette. It is intentionally small and action-oriented, not a second full
launcher.

- It opens on =$mod+Shift+/=
- It includes the high-value workspace jumps, session mode toggles, tmux
  save/restore/chooser, lock, and the existing workspace chooser
- Entries include the matching keybinding in the label so the menu doubles as
  rediscovery/help

* Tmux

The terminal layer is now intentionally hybrid:

- =sway= owns workspace switching, app routing, scratchpads, and a few
  global tmux entry points
- =tmux= owns panes, windows, sessions, and save/restore
- =~/.local/bin/rg-tmux-role= is the authoritative glue command

The main terminal rules are:

- prefix is now =Ctrl+a=
- pane movement uses =h n e i= to match the Colemak/kanata movement model
- =prefix w= opens the window chooser
- =prefix s= opens the session chooser
- =prefix Space= opens the tree chooser
- =prefix S= saves tmux state
- =prefix R= restores tmux state

Restore is explicit rather than magical. The user service
=tmux-restore.service= runs =~/.local/bin/rg-tmux-role restore=, which will
start the tmux server, run =tmux-resurrect= if available, and ensure that the
named =mS= and =subFloat= sessions exist again for the sway scratchpads.

Cross-workspace app launches now also have a small watcher service:
=rg-sway-route-watcher.service=. It emits a short notification such as
=PDF -> 7: read= only when a newly created window lands on a workspace other
than the one currently focused. These route hints are low-urgency and
stack-replaced so repeated launches do not flood notification history.
