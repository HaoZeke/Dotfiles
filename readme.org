* About
For historical purposes, the older versions of my Dotfiles are
retained as branches. However, the ~chezmoi~ approach is current.

A key understanding of the workflow here is that Dotfiles should be
per machine, and not generically per configuration.

By leveraging template substitution, conditionals can be eliminated from the
actual shell scripts, which allows for a faster shell. This does come at the
cost of portability, without the backing ~chezmoi~ machinery, the scripts are no
longer very portable.

** Usage
To get started, we need:
#+begin_src bash
sh -c "$(curl -fsLS chezmoi.io/get)" -- init --apply HaoZeke --branch chezmoi
chezmoi init
#+end_src
Note that the ~chezmoi init~ command is being run twice, to grab some sensitive
information which needs the encryption settings, as [[https://github.com/twpayne/chezmoi/pull/1521#issuecomment-940840570][discussed here]].

** rglat5340
Installed from hzArchiso with ~hz-install --profile rglat5340~. The role
gates it shares with ~rgx1gen11~ cover the shell environment, the x-cmd
bundle, KSM, ananicy, realtime audio, the session OOM baseline, memory and
zram tuning, network ingress, the terra mail tunnel, and orgaw.

The hardware gates stay per host. The ThinkPad trackpoint, power bindings,
plymouth resume, TLP baseline and ~linux-rg~ fragment stay on ~rgx1gen11~.
The 5340 has its own ~run_onchange_linux_rglat5340_power.sh.tmpl~ and
~dot_local/share/rglat5340/tlp-00-base.conf~: Dell platform profile
balanced on AC and quiet on battery, charge thresholds 75 to 90, and the
LPSS I2C controllers of the ELAN touchscreen and touchpad pinned on.
~run_onchange_linux_rglat5340_system.sh.tmpl~ sets up the greetd and tuigreet
login into ~start-sway~, uinput and the input group for kanata (Colemak),
and enables bluetooth, tailscaled and sshd.

EESSI is the primary software stack there. The same script mounts
~software.eessi.io~ system-wide through ~cvmfs-eessi.service~, running
~cvmfs2 -o libfuse=2~ with CERN's el9 fuse2 libraries in ~/opt/cvmfs-fuse2~,
because the fuse3 path of the Arch package never answers a read. It needs
the AUR ~cvmfs~ and ~cvmfs-config-eessi~ packages. ~eessi [VERSION]~ in any
shell then loads the stack:
#+begin_src bash
eessi 2025.06 && module load GCC/13.3.0
#+end_src

Three ~rgx1gen11~ pieces are not extended yet. Meta oomd needs its stage
tarball on the host first, and the two cosmoet relay forwards name the X1
itself.

First apply, as the user, after the age identity is at ~~/key.txt~:
#+begin_src bash
chezmoi init --apply HaoZeke --branch chezmoi
#+end_src
The Livingston stack and the full assistant profile come from the sealed
store; unseal it before the second apply.
